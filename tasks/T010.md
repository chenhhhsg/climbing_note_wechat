# T010 独立试用工程的本地照片持久化与归属索引

## 背景与问题

用户已选定先接入独立试用工程，真机和正式账号隔离另列验收。本轮先建立可复用的持久照片层，下一轮再接页面；对应产品 LP03、LP05–LP09、LP13 的存储逻辑及迁移保留条件。

先读产品验收文档、`devtools/gym-log/utils/store.js`、`utils/trial-save-server.js`、已有测试和根配置。依赖 T009 的 QA PASS 候选；frontmatter 的 baseline 是规划参照，实际执行起点须包含 T009 已审提交，并记入报告。本轮不依赖真实云环境。

## 开发范围（允许修改）

- `photo-files.js` 封装真实小程序文件、压缩、尺寸/体积读取与缩略图操作，同时可注入可控测试适配器。
- `route-photos.js` 提供保存/更换、按线路读取、移除和失败恢复入口。调用显式绑定试用 ownerId、独立数据集标识和稳定 routeId；操作启动时固定归属。照片索引与可重建缓存分开，照片标识与 `local` 存储位置分开。
- 主照片由选择器临时文件转换为用户文件目录中的持久文件；索引使用独立命名空间，采用可重启恢复的格式。主图压缩后保留完整画面、提供缩略图；300–800 KB 为试验目标，不冒充已核验硬上限。
- README 记录服务契约、数据版本、专用目录/键、失败恢复、重试和将来本机转云的保留方式。新增对应离线测试与执行报告。

## 禁止变更

不改页面、正式工程、正式用户资料、原场次/尝试存储、AppID 或云配置；不增加云上传/迁移、真实登录、多图相册或外部依赖。不把昵称头像、全局当前线路或公共缓存键当成用户归属；不把临时路径直接写成成功关联。不清空全部存储或用户文件目录；清理仅限本服务可证明无引用的文件。不修改任务状态和批准内容。

## 验收标准

- [ ] **PS01 持久化**：保存完成后，原临时文件失效且服务实例重建，仍能由 owner/数据集/线路查到同一 photoId，并读取持久主图与关联；成功仅发生在文件和索引均完成后。用开发者工具实际文件系统保存一张授权或生成的无个人数据样例，重载后复读，证据放仓库外。
- [ ] **PS02 归属**：虚构 A/B、两条同色同级线路以及不同试用数据集分别保存，读取/更换/移除互不串线或串用户。缺少必要归属时返回可识别错误；新数据集不得错误继承同编号旧线路照片。此项是注入身份测试，不声称验证了微信账号隔离。
- [ ] **PS03 原子结果与恢复**：分别注入压缩、文件写入、索引写入失败及步骤间中断。新建失败不留假成功索引；更换失败保留旧可读照片；重试后仅一个有效主照片引用。重启可处理未完成操作和孤立文件，不能误删仍被引用的主图。
- [ ] **PS04 重复与乱序**：重复保存/重试不重复提交同一次操作；旧更换回调不能覆盖更新版本，旧保存回调不能恢复已移除照片。串行、重复、并发和实例重建后分别断言主图、索引与 operation 状态，不能只检查返回文案。
- [ ] **PS05 移除与文件缺失**：移除只影响指定归属；删除/索引失败返回可恢复状态，不能虚报成功。读取缺失文件返回明确的不可用结果，保留可供页面处理的状态，不返回其他线路照片。
- [ ] **PS06 迁移保留与回归**：photoId 不以临时路径为身份，`storage` 类型和位置可区分；本轮仅 local 实现，不发起云调用。真实文件适配器有执行证据，全部既有回归与新增故障测试通过、无跳过，改动仅限 scope。
