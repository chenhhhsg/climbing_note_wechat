# T054 单线记录从整张把次卡开始长按删除

## 背景与问题

负责人补充要求。现有「第 N 把」序号框的删除触点偏小。长按入口扩到单线记录里选中把次的卡片主体，在现有确认框前新增「删除这一把」菜单选项。此项随 T051–T053 在同一候选验收。

## 开发范围（允许修改）

把带原档案、场次、线路、把次、版本及页面令牌的长按绑定移到把次卡主体。最新把、收起和展开的旧把均支持。按编号、结果、时间、正文和内边距都命中所选卡。长按后先开菜单，选「删除这一把」才展示该原把和本机视频删除范围。沿用 `requestDeleteAttempt` 的原归属、旧快照与版本校验、确认和回执处理。两步可取消。菜单、确认框的失败按原生接口对象处理并可见重试。备注、视频、撤销、编辑区等控件保持独立，短按展开/收起按原规则。

## 禁止变更

保留实际把次删除、撤销资格、原把次 ID、编号补位、备注及视频清理语义。保留系统相册原片及其他把次。禁止按显示顺序删除或修改 T051–T053 的整场删除。

## 验收标准

- [ ] 从最新把、收起旧把、展开旧把的卡片主体打开菜单，选择后才显示所选原把与视频范围。取消菜单或确认均无写，卡片状态一致，松手不误展开。
- [ ] 备注、回看视频、撤销及编辑区各自正确响应。两次确认、旧页面事件、内容或版本变化仍按原归属校验与幂等规则处理。
- [ ] 用现有测试覆盖删除旧把、原顺序补号、原备注和视频归属、失败重试、重开清理、共享引用与撤销资格。原序号框的静态 WXML 检查改为整卡绑定检查，其余删除语义测试保留。

## 建议验证命令

```powershell
node --test tests/training-attempt-delete.test.cjs tests/training-attempt-undo.test.cjs tests/training-record-note-withdraw.test.cjs

```

## 测试与人工验证边界

离线验证严格的菜单/确认参数、原 ID 与边界。手机实际按住卡片空白、结果或时间、展开后正文分别核对。坐标长按证据以实际原生触点为准。

## 回滚办法

合入前在隔离工作区回退 T054 的交互提交，保留接受过的原把次删除实现和既有试用数据。
