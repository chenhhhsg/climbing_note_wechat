# T008 弱网重试：丢失保存响应后重试同一次尝试

## 背景与问题
依赖 T007 已审候选。在同一离线试用工程模拟保存端已入账而回执丢失，实现获批计划中的可操作弱网验收。

## 开发范围（允许修改）
在既有路径接入小型本地模拟保存端（与客户端待确认操作分开），按同一操作 ID 幂等。提供一个显式的试用操作“模拟下一次保存回执丢失”，仅用于该次保存。
旧汇总只读；局部存储是测试替身，真实跨设备、服务端权限/幂等并发单列待验。

## 禁止变更
禁止访问真实服务、声称已验证云端事务、把重试建为新的尝试、将故障注入带入正式页面。 不改任务状态、其他任务或 pm-reports；不自动合并、推送、发布。

## 验收标准
- [ ] 用户点结果后可见保存中、失败并保留原条目；在该行重试复用同一 ID。服务端模拟账本已保存但回执丢失、重复/并发重试、页面重进后重试均不重复；成功后再点结果生成新 ID。
- [ ] 复跑周四两次＋周日一次，故障注入第二把，重试后仍三次且备注正确；保存中不可重复派发同一次，其他场次/线路归属不串。Node 必须分别断言持久账本、待确认状态和页面计数。支持用户在开发者工具亲自复现，记录入口。
- [ ] 在实际候选上复跑下列命令，使用真实实现，记录退出码、通过数、阻塞及证据。差异仅限 scope。可将模拟器和运行日志留在仓库外 D:/climbing_note/_batch-evidence/T008/，不要把截图加入正式工程。避免无关扩展。
