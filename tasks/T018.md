# T018 本机训练历史、跨天接续与旧记录只读回看

## 背景与问题

正式记录 tab 和旧详情按 `climbing_records._id` 读取。独立工程已验证同一路线跨日回看及历史完攀纠错。先读 `pages/record-list`、`pages/record-detail`、`utils/db.js`、原列表首屏/分页/刷新竞争用例、独立工程线路详情与 T016–T017 的真实档案接口。

## 开发范围（允许修改）

把正式记录 tab 的本机训练历史接入长期线路详情，按本地日期和场次展示逐把结果及备注，可选当日场次再记；既有云汇总保留明确的「旧记录」入口和原 ID 路由。本单的旧数据回看只读。为后续照片提供同一档案和长期线路 ID。

## 禁止变更

不扫描猜测的环境/集合，不开放云权限，不伪造旧训练，不按名称、颜色、难度自动归并。旧来源和新档案不得混用列表计数、路由 ID 或图片引用。T002 的分页、失败重试与刷新竞争覆盖须保留。

## 验收标准

- [ ] 第一天两把未完成、第二把有备注；第二天从历史打开同一条线，在新场次记完攀，显示两天两场三把。打开历史本身不建场次。另一天或同日有多个场次时保留原归属；旁线数据不变。
- [ ] 从跨日详情对第三把点「改为未完成」，重开仍是三把零完攀，原时间、场次与备注均在；再完攀后四把一完攀。同一坐标双击只改指定把次，有多条有明细的历史完攀时更正另一把须点其对应记录。
- [ ] 旧列表保留原分页与账户访问边界，旧详情按原 `_id` 读原字段与图片。如「尝试 5 次、完成」仅显示一条历史汇总；只读浏览不得更新、删除、拆成五把或并入本机统计。同字 ID 的新线路与旧汇总进入各自详情。对已知 `climbing_sessions.routes[]` 旧形状保留原汇总或已有明细的语义，未核实数据来源时用夹具验证兼容读取，不自动接入新集合。
- [ ] 旧云有数据、空库、拒绝访问或不可用时显示有区别的状态。断网或云请求迟到时，本机历史、线路详情及继续训练可用。旧库读失败不能触发回写、清空或覆盖本机档案。
