# T025 记录逐把视频时间点并从原把次回看

## 背景与问题

逐把视频本机副本、原把次入口与播放已合入主线。用户要在同一段视频里记下容易掉落或需要复盘的位置，下次从原把打开并跳回那个时刻。T026 是功能前置。本草案以 T048–T050 收尾后的 main `57fedbfc8e6a` 为基线，并把长按删除与共享副本清理纳入回归。[原首版交付边界](../docs/product/逐把视频本机回看-v0.1-整项验收.md)

先读现有视频页、播放事件与来源令牌、本机索引读写、替换移除及把次删除的定向清理。整项验收见下方链接。[整体验收标准](../docs/product/逐把视频手工时间点-整项验收.md)

## 开发范围（允许修改）

- 复用原把次的视频页。已保存且播放器时间可用时提供「记下当前时间」，显示可点回、可移除的时间点列表，按时间排序。首版只记时间。
- 用原播放器对当前已保存片源报告的时间，持久化整数毫秒，调用现有播放器跳转时换算为秒。沿用现有来源令牌与实际播放器实例。元数据或当前时间还未可用时给出明确信号。
- 建议把时间点作为当前片段索引项的可选数据。归属核对档案、场次、线路、原把次、片段 ID 和版本。旧索引缺字段按空列表读，打开页面无写入。失败后的重试沿用同一操作身份。
- 时间点随原片段生命周期。取消更换保留原列表，确认更换只读新片时间点。移除视频副本或长按永久删除把次后移除原关联的时间点，其他把次及仍被引用的文件保留。复用既有索引结清，无需新增文件清理路径。

## 禁止变更

训练记录、照片、统计及现场手势的语义保留。沿用现有本机视频路径和 AppID。云上传、跨机同步、AI 分析、视频页整体改版、逐把备注改造均留在已有后续范围。测试样片和截图留在正式包之外。

## 验收标准

- [ ] 给同线两把中的 B 保存视频，在 B 的播放位置记点。重开与跨场历史回看仍只从 B 读取同一片段的标记，A 与同名异线数据一致。
- [ ] 覆盖 0 秒、片尾、元数据未就绪、片源缺失、非法时间、切换片源及迟到回调。合法值按整数毫秒读取，跳转请求用秒。列表和提示区分保存目标与原生实际落点。
- [ ] 连点、写入失败和写回执丢失分别验证。失败保留已有时间点并可重试，同一次动作只新增一个点。移除单点只删除该点。
- [ ] 取消更换保留原片和时间点。确认更换、移除副本、撤销后重记、长按永久删除，以及共享视频索引故障后重开，均核对原把次、片段版本、附件和标记归属。应用内普通清缓存保留在用标记。

## 测试与人工验证边界

- 离线断言归属、毫秒转秒、失败重试和旧数据兼容。
- 微信开发者工具使用带烧录时间码的 30 FPS、60 FPS 本机样片分别核对保存读数、`seek` 请求与实际画面，目标差值不超过 0.5 秒。
- 负责人用同一候选在手机微信复验真实解码、冷重开和原把次入口。只记录实际验证的系统、微信版本和画面误差。

## 回滚办法

在隔离工作区撤回本单的实现并复跑视频、永久删除与训练回归。旧代码可继续读取既有索引、记录和视频文件。保留试用数据，回滚操作无需清缓存或删除本机文件。
