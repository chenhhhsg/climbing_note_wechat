# T038 明确逐把视频保存在当前手机的攀笔中

[整项验收](../docs/product/线路历史与照片动作标记-v0.1-整项验收.md)

## 背景与问题

逐把视频候选已支持本机持久副本。选片确认仍写「保存到本机」，用户难以辨认副本位置及回看的入口。

## 开发范围（允许修改）

以视频候选的 `pages/attempt-video/`、`utils/attempt-video-playback.js` 为入口，首次确认按钮写「保存到攀笔」。旁边显示「视频副本保存在这台手机微信里的攀笔中，不上传云端。可从这一把的记录中回看。相册原片保留。」首次成功反馈写「视频已保存到这一把」，仍只在原持久服务确认后展示。更换、错误及移除提示按同一存储口径复核。

## 禁止变更

不改选片接口、播放器与保存流程、视频索引、路径、空间规则或缓存策略。视频上传、云同步和手工时间点后置。

## 验收标准

- [ ] 从明细和跨日历史打开同一把，预览时显示「保存到攀笔」及保存位置、回看入口、相册原片和无上传的说明。
- [ ] 只有可靠提交后出现「视频已保存到这一把」。取消、写失败和回执不明确时不显示成功。现有替换和移除提示与行为一致。
- [ ] 按现有清缓存入口和原把次回看测试，副本字节、片段版本、把次与备注一致。同线另一把无关联，视频操作不发起上传。

## 建议验证命令

~~~powershell
node --test tests/attempt-video-playback.test.cjs tests/attempt-video-files.test.cjs tests/training-flow.test.cjs
node --test tests/*.test.cjs
git diff --check
~~~

## 测试与人工验证边界

离线复跑提交与清缓存保护，开发者工具核对按钮、提示和实际播放。负责人在同一候选从原把次保存、清缓存后播放，并复述副本保存位置。

## 回滚办法

在集成工作区按依赖逆序撤回本任务代码，复跑原训练页、视频和照片入口。保留已存训练、照片、标记和视频数据。
