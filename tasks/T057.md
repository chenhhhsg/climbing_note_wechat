# T057 R2 保住视频失败副本的清理凭据

## 背景与问题

按 2026-11-20 复审交接执行。以上一通过自测的任务作为集成前置，验收绑定本批最终提交。

## 开发范围（允许修改）

同一所有权索引区分副本已清、待清和状态未知。仅在确认缺失或删除后移除 pending。目录快照中目标未出现时，检查在途写入并重新核对文件。页面按实际结果给出提示。

## 禁止变更

保留现有页面结构、试用资料、已验收归属、普通清缓存保护及未涉及的行为。禁止改动 AppID、实际 CloudBase 配置与权限，禁止在生产档案或真实云端注入故障。合并和发布由负责人另行授权。

## 验收标准

- [ ] 首次保存与更换分别注入复制后 access/stat 失败及 unlink 失败，凭据保留，恢复后只回收失败副本。
- [ ] 挂起复制并同时清理与恢复，pending 不提前消失。索引临时读取失败或重开后仍可按原证据恢复。
- [ ] 旧片、旧时间点、相册原片及未知文件保持。原正常视频和整场删除回归通过。

## 建议验证命令

```powershell
node --test tests/*.test.cjs
git diff --check
```

## 测试与人工验证边界

先用合成档案、严格微信参数对象及可恢复故障验证。按分批验收单在同一冻结提交复核适用的原生页面、正式构建和手机待验。

## 回滚办法

回退本批隔离分支中的任务提交并复验既有记录读取。验收资料与当前试用工程保留。
