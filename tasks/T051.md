# T051 按原 ID 一次提交本机场次删除

## 背景与问题

两处入口共用一个本机场次删除操作。先读 `utils/training-store.js` 的场次、有效把次、存档读写和迟到保存逻辑，以及 `utils/training-session-summary.js` 的同日编号和统计口径。规划基线在 T025 处理后核对。T052 消费本任务的档案接口。

## 开发范围（允许修改）

按 `archiveId + sessionId` 提取当前目标及确认所需的范围与状态。存档前重读并核对原日期、岩馆、场次和本场关联的实际内容，识别把数不变但结果、备注或原把变化的情况。持久待办命中本场时拒绝提交并给出可操作提示。一个档案写入移除该场、其线路关联和全部把次（含已撤回），同时更新活动指针。提交失败时按现有读回语义区分确认未写入、写入成功但回执丢失和状态未能确认。

删除当前场选同日同馆剩余的最近一场，并清理失效的线路指针。没有可接续场时清空当前选择。删除非当前场保留原选择。复用已有同日展示编号，保留后续原 ID、内部 seq 和单调序号计数器。保留长期线路与照片归属。

## 禁止变更

保留长期线路、岩馆、照片、清单、其他场次和旧云端数据。按本机档案原格式提交，保留既有把次删除、撤回、恢复及保存重试语义。媒体清理与页面交互由后续任务接入。

## 验收标准

- [ ] 空场、有线路未记把、有效和已撤回把次混合场次均能正确核对和删除。目标已消失或档案变化时旧确认不能删另一场。
- [ ] 同日同馆、同日不同馆、上一日以及活动/非活动场次覆盖。显示补号，其他原 ID、数据、序号及对应统计可复核。删除最后一场后新建使用新 ID。
- [ ] 在途保存、撤回、恢复、更正及过期确认拒绝写入。覆盖档案写入前失败、回执丢失及重读失败；存储未知不报已完成。带原场次 ID 的迟到请求无法写入接续场。

## 测试与人工验证边界

离线用合成档案核对存档前后的对象、计数、活动指针与失败重读。首页、场内、小结和历史的页面结果在整项候选中复核。

## 回滚办法

在隔离工作区退回未合入的任务提交，以新建测试档案重复验证。回滚代码不恢复已经确认删除的记录，试用档案保持原样。
