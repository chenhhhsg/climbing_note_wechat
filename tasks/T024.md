# T024 原生播放、失效后重选与解除逐把视频关联

## 背景与问题

关联完成后，用户需要从原把直接播放。临时路径在微信重开后可能已经失效，历史仍应能找到原把。 [批次验收](../docs/product/手机反馈与逐把视频-批次验收.md)

## 开发范围（允许修改）

在正式视频页使用原生 video，实现可见的播放、暂停、读取错误、重选与确认替换/解除。根据当前片源是否可读选择播放或提示重选。区别同一原片与更换后的片段，以稳定标识和可核验内容或安全的显式重新绑定处理。

## 禁止变更

不删除系统相册原件，不执行云上传，不新增 AI 或远程播放器依赖。

## 验收标准

- [ ] 对 B 选片后，真实播放器可播放并暂停。重开时原片仍可读则可再次播放；模拟临时文件丢失时明确显示「需重新选择原片」，把次、归属和备注仍可读。
- [ ] 重选或替换先预览，取消后原关联保留。确认替换时使用正确片段标识；相同名称和时长的不同文件不能静默继承旧片身份。旧播放器迟到的 ready/error 回调不覆盖当前新片。
- [ ] 解除关联需明确操作，重复操作只解除一次，A 的视频、B 的把次和系统相册文件均保持原值。断网、损坏文件及选择器真实失败时页面可继续操作。

## 建议验证命令

~~~powershell
node --test tests/attempt-video-playback.test.cjs
node --test tests/*.test.cjs
git diff --check
~~~

## 测试与人工验证边界

离线测试记录状态和原生调用；QA 使用授权的合成片段在开发者工具实际播放，记录画面、可见时间和错误提示。真机编码兼容与权限另行记录。

## 回滚办法

在隔离候选中按依赖逆序撤回本单的实现，复跑前序用例。保留已存在的持久媒体、用户记录和索引，回退版本只读取其支持的格式。
