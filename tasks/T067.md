# T067 备份核心 文本快照、隔离恢复与失败保护

## 背景与问题

按 2026-11-20 复审交接执行。以上一通过自测的任务作为集成前置，验收绑定本批最终提交。

## 开发范围（允许修改）

定义版本、时间与统计摘要的文本封套。导出训练、备注、独立清单及明确列出的辅助数据，可按指定本机键导出受损诊断原文。照片、视频、各自索引和操作日志不包含。先严格验证档案身份、跨表引用、ID、计数及大小，隔离预演。正式恢复采用新档案归属隔离旧媒体，保留此前状态；对档案与清单联合写入采用可重启核对与恢复的提交记录，故障中保留原档案可读。避免把本地写入自动升级为迁移。

## 禁止变更

保留现有页面结构、试用资料、已验收归属、普通清缓存保护及未涉及的行为。禁止改动 AppID、实际 CloudBase 配置与权限，禁止在生产档案或真实云端注入故障。合并和发布由负责人另行授权。

## 验收标准

- [ ] 样本场次、长期线路、逐把备注、清单与明确辅助字段文本往返，摘要以实读验证为准。损坏、未来版本、引用错配和输入过大无写。
- [ ] 确认前预演零活动档写入。注入每个提交点、回执和重开故障，训练与清单不出现半提交可见状态，原档可读且既有媒体均保留。
- [ ] 报告实际摘要字节数和隔离样本保存耗时。旧档结构兼容，不把模拟上限或一次耗时当产品承诺。

## 建议验证命令

```powershell
node --test tests/*.test.cjs
git diff --check
```

## 测试与人工验证边界

先用合成档案、严格微信参数对象及可恢复故障验证。按分批验收单在同一冻结提交复核适用的原生页面、正式构建和手机待验。

## 回滚办法

回退本批隔离分支中的任务提交并复验既有记录读取。验收资料与当前试用工程保留。
