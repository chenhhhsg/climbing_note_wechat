# T001 记录列表首次加载、刷新与分页修复

## 背景与问题

`pages/record-list` 首次进入一直停留加载；第二页失败时页码已推进，重试漏记录；下拉刷新与翻页存在相互覆盖的竞争窗口。完整背景、故障定位与验收用例见 `docs/tasks/001-记录列表修复与回归验收.md`。

## 开发范围（允许修改）

- `pages/record-list/record-list.js`
- `pages/record-list/record-list.wxml`
- `pages/record-list/record-list.wxss`
- `tests/record-list.test.cjs`
- `docs/reviews/001-记录列表执行报告.md`

## 禁止变更

- 不修改 `utils/db.js` 的 `getRecords(page, pageSize)` 契约、旧记录字段、云权限、AppID。
- 不动首页、统计页、导航、视频与 AI 相关代码。
- 不写入或清空真实云数据库。

## 验收标准

- [ ] L01 首次 `onLoad` / `onShow` 只请求一次 `(1,20)`；空集合显示空态
- [ ] L02 旧记录字段完整保留，按原 `_id` 打开现有详情页
- [ ] L03 返回列表刷新时用新第一页整体替换，同一条记录不重复
- [ ] L04 首屏失败显示可恢复错误态，重试命中第一页
- [ ] L05 下拉刷新失败保留旧记录并结束动画，重试后替换
- [ ] L06 第二页失败后重试请求序列为 `1,2,2`，最终 21 个不同 ID
- [ ] L07 刷新与旧第二页竞争时，过时结果不覆盖新第一页
- [ ] `node --test tests/record-list.test.cjs` 全部通过

## 建议验证命令

```powershell
node --test tests/record-list.test.cjs
git diff --check
```

## 测试与人工验证边界

- 离线测试覆盖：页面状态、请求顺序、错误恢复、刷新/翻页竞争。
- 需要开发者工具验证：从底部「记录」进入、打开详情、返回刷新、下拉。
- 需要真机验证：弱网下翻页与刷新；真机媒体相关验证不属于本任务。
- 需要云环境验证：真实集合的分页行为；本任务不写入真实数据。

## 回滚办法

```powershell
git checkout -- pages/record-list
Remove-Item tests/record-list.test.cjs
```
