# T052 清理该场的本机视频引用并支持重开重试

## 背景与问题

接续 T051。先读 `utils/training-attempt-delete.js` 的持久凭据、原 ID 防重、启动恢复，以及 `utils/attempt-video-files.js` 的 `removeDeletedClip`、索引写回和共享引用。整场删除含已撤回把次。需要确保档案未确认删除时附件仍在，档案已删除后即使文件操作失败也能继续清理。

## 开发范围（允许修改）

给两个页面提供同一确认快照与删除协调器。核对档案、原场次、把次及片段 ID、版本和文件归属。确认期间换片、移除附件或发生等数量变化时要求重新确认。按本场关联计算视频数。在动档案前持久记录所需的定向清理依据；确认档案删除后，逐条清理目标引用，复用已有视频所有权检查和原生文件适配。存储未能确认时保留待核对凭据，重开或可见重试按档案状态结清。共享被保留的结果算已完成。无待办启动时不扫描媒体目录。

把整场删除与同场的逐把删除、在途视频写入以及迟到保存协调。`training-store.js` 的追加改动限原 ID 保存防重与删除状态衔接，`training-attempt-delete.js` 和 `attempt-video-files.js` 的改动限共享调用、同场在途判定、参考完整所有权证据的清理。保护已有快照和凭据的读取兼容。

## 禁止变更

保留剩余引用的视频文件、相册原片、其他档案、线路照片及标记。禁止按文件名、编号、日期或目录批量删除。保留旧云端数据、视频播放器交互、AppID 与云配置。

## 验收标准

- [ ] 先模拟确认取消和档案未写入，所有媒体及引用保持原值。确认删除后，目标独占副本移除，其他场次的共享副本和引用有效；本场已撤回把次关联也被清理。
- [ ] 重复确认、档案写入回执不明、视频索引读写失败、文件删除失败与重开恢复均可复验。共享保留会结清，旧档案 ID 或版本不匹配不删文件。
- [ ] 已退休的原把次 opId 在其他场次重放、旧页面把次保存或视频回调不会复活关联。正常新 ID 可继续记录。跨档案同 ID 隔离，凭据无法读取时不推断安全。

## 建议验证命令

```powershell
node --test tests/training-session-delete-media.test.cjs tests/training-attempt-delete.test.cjs tests/attempt-video-files.test.cjs
node --test tests/*.test.cjs
```

## 测试与人工验证边界

离线用隔离内存档案、索引和文件适配器验证故障与引用；整项 QA 在开发者工具验证实际重开和再次播放，负责人在手机确认相册原片仍可打开。

## 回滚办法

发布前仅在隔离工作区回退任务提交。若已在测试档案发生永久删除，以新的合成档案复现实验。保留现有试用档案与未处理的清理凭据。
