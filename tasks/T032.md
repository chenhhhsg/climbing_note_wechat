# T032 同一把次撤回、恢复与有效计数

## 背景与问题

saveAttempt 通过已保存的 opId 去重，未完成的保存与完攀更正各有待处理记录。除训练存储外，首页、场内、统计、场次小结和想爬清单都直接消费把次。撤回必须给这些使用者提供一致的有效读数。 [整项验收](../docs/product/场内操作简化-v0.1-整项验收.md)

## 开发范围（允许修改）

在正式本机训练档案内实现可重试的撤回、恢复，保留稳定把次 ID、原序号、归属、时间、结果与备注。按档案、场次、线路、把次和预期状态校验写操作；读最新持久状态再写。保留原保存请求的去重凭据。审计历史分组、把次标签、有效计数、完攀锁定、更正目标、清单和小结，共用同一口径。旧档案所有已提交把次默认有效，只读打开不迁移、不改原字节。

## 禁止变更

不物理删除原把或线路，不伪造相反结果代替撤回，不动照片文件、存储位置、自测分数或旧云汇总，不引入云写或视频。更多存储迁移或其他路径需另提范围。

## 验收标准

- [ ] A 线已有 2 把，带备注的第 3 把撤回、恢复得到 3→2→3。同一意图重复调用只产生一次效果；恢复后 ID、原序号、结果与备注一致，其他把次及同色 B 线保持原值。
- [ ] 覆盖写前失败、写入已成功而回执失败、重开、重复请求、迟到的 saveAttempt(opId) 及旧撤回/恢复回调。延迟操作不能使已撤回把次复活、撤销后来成功的相反操作或改写已切换的档案/场次。不得只在内存去重。
- [ ] 唯一一把已确认的抱石完攀被撤回后可继续记录，恢复后锁定；存在其他有效完攀或待确认完攀时重新计算并给出冲突状态，恢复不可制造第二次有效抱石完攀。顶绳、先锋沿原规则。原「改为未完成」仍保留一把。
- [ ] 首页、场内、线路逐把历史、跨天历史、底部统计、场次小结和想爬清单按同一有效集合计算；已撤回把次不贡献把数、最近有效备注及完攀，待保存记录不计入。照片、卡点、体测及旧云汇总保持原归属。
- [ ] 基线旧档案、同日多场、跨天、多档案有同名 ID、撤回后再保存新把均有隔离测试。新把的持久 ID 唯一；故障后按原意图重试，不覆盖其他场的后续写入。

## 测试与人工验证边界

Node 用真实存储模块和可注入故障的虚构档案取证，对比持久记录、各读数与原图摘要。物理断网、杀进程重开和设备回看在整项 QA／负责人阶段分开登记。

## 回滚办法

先在隔离工作区回退界面入口，保留撤回元数据与去重凭据。用旧、新两版复核合成档案读写兼容，再决定可用的回退版本；不得通过清档或让旧写入程序丢失撤回状态来回退。
