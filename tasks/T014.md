# T014 抱石首次完攀的保存与重试

## 背景与问题

依赖 T013 的线路类型与读取规则。`today.recordAttempt` 按场次和线路拦截待确认项，`trial-save-server.submitOperation` 按 `opId` 去重。另一个场次或新操作 ID 仍有机会给同一抱石线路重复入账。先读这两处及 `dispatchPending`、`finishDispatch`、`retryPendingAttempt`、试用身份和 G21–G31。

## 开发范围（允许修改）

仅在 frontmatter 列出的文件内实现共享的完攀判定、创建待确认操作、保存账本和回执恢复。以当前试用用户与长期线路 ID 标识归属，沿用当前数据集边界。向 T015 提供可以直接复用的状态判定。负责人于 2026-11-09 补充批准两处测试数据调整：PU01 把完攀放在最后一次尝试，PL03 在尚未完攀的线路制造待确认记录。原有照片、清缓存及把数断言全部保留。

## 禁止变更

不接入正式账号或云服务。旧账本、历史多次完攀、旧汇总、照片和备注均须保留。不可依赖隐藏按钮、禁用时间窗口或一次页面实例的内存标记来保证唯一性。

## 验收标准

- [ ] 同一抱石线可连续提交未完成。首次完攀被确认后，跨场次、跨页面以不同操作 ID 提交完攀或未完成，均不能新增待确认项或把次。直接调用实际模拟保存入口也不能增加账本行。
- [ ] 分别模拟落账前写失败、已落账丢回执、收到回执但本地确认写失败。待确认与原把次可恢复；同一操作 ID 重试能取回对应结果。确认前在另一个场次或页面尝试另起操作，最后账本与本地均只有一次新增完攀，原待确认可清除。
- [ ] 连点、并发重试及旧页面迟到回调都不覆盖新状态。对已有两把未完成的线路断言最终三把、完攀一把，逐项核对 ID、备注和所属场次。测试另一个同色同级 ID、同 ID 的独立用户上下文及重置后复用编号的独立数据集，确认不会误锁。
- [ ] 旧 V 级线路及旧账本可兼容读取。历史已有多条完攀时展示原数目，之后无法新增；仅有旧汇总时不生成逐把明细。顶绳和先锋完攀后可再记，保留相同操作 ID 的幂等重试行为。
