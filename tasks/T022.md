# T022 从底部统计查看本机把数与实际完攀

## 背景与问题

负责人反馈底部统计无法使用。当前 `app.json` 已注册该 tab，统计页通过旧云接口读取 `climbing_records`。在本机有三把、一次完攀时，空云库返回 0/0，缺少云能力还会提示加载失败。[基线证据与联合验收](../docs/product/手机验收跟进-重量输入与本机统计.md)

## 开发范围（允许修改）

在现有正式统计页复用 `utils/training-store.js` 的只读入口，按当前本机档案的已提交把次汇总。本机把数、完攀、未完成及完成率使用同一分母。本月按把次所属训练日期计算；地点、类型按岩馆和长期线路关联。现有最高难度如继续展示须区分 V 级和 YDS。保留旧云汇总的只读访问；若在统计页展示旧云数字，单列来源，让本机结果优先显示。返回 tab、下拉刷新和冷启动均重读当前状态。

## 禁止变更

不改 tabBar、云配置、身份权限、9c 计分或训练写入逻辑。不把旧云汇总次数、待保存操作或 9c 等级计入本机把次。不得迁移、清除、重写训练档案、照片或自测记录。

## 验收标准

- [ ] 从底部「统计」进入，空档显示明确空态；在同一场次保存两把未完成和一把完攀后，显示本机 3 把、完攀 1、未完成 2，完成率按现有取整规则为 33%。断网及旧云拒绝、空数据、迟到响应均不遮挡或覆盖本机数字。
- [ ] 将原完攀更正为未完成后再进统计，显示 3 把、0 完攀、3 未完成、0%。同一次操作重试不产生额外把数。重开、刷新、切 tab 后一致；保存或更正 9c 成绩后这两个总数保持 3、0。
- [ ] 用跨日、同日多场、同色同级不同线路验证把次按原 ID 计数，未落盘的把次不计入。旧汇总「尝试 5 次、完成」仍可只读回看，本机数字不增加。损坏档案显示读取失败并保留原字节，和真实空档可区分。
- [ ] 只进入、刷新、退出统计后，本机训练、自测、照片索引和原图均与进入前一致。允许用合成云数据覆盖旧接口错误，无需真实用户身份。

## 测试与人工验证边界

离线用真实训练存储和统计页方法覆盖更正前后、错误、云延迟和缓存隔离。在开发者工具通过底部 tab 点开验证入口及可见读数，手机微信再确认可用。原反馈没有注明点击后的具体画面；若真机仍异常，记录入口、页面或提示与候选 SHA。

## 回滚办法

在隔离分支撤回本单的统计页与测试改动。既有训练、照片、自测与旧云历史沿用原路径回看。
