# T016 正式记录版本机档案、保存重试与缓存保护

## 背景与问题

T013–T015 已在本地 main 收尾。负责人选择新训练先存本机。正式启动仍有占位云环境，`utils/db.js` 在模块顶层取云数据库，个人页普通清缓存会调用 `wx.clearStorage`。独立工程有虚构岩馆、固定试用身份和模拟保存端。先读这些入口、`utils/grade.js` 及 `devtools/gym-log/utils/{store,route-rules,trial-save-server}.js` 的既有规则。

## 开发范围（允许修改）

在正式 `utils/` 提供本机档案读写与三类线路规则。用本地持久档案 ID、稳定的场次/线路/把次 ID 和操作 ID 维护岩馆、场内关联、当前选择、结果及备注；写入和纠错必须可恢复。保护必需键、未来照片索引及正在进行的操作，普通清缓存仅清可重建内容。云客户端延迟到实际旧记录调用时取得，保留旧接口的调用契约与错误语义。正式新增 utils 会改变包清单；只调整包测试内 39/41 两处固定计数及必要夹具，按实际清单核对条目，保留缺文件、禁止项、损坏包的反例。

## 禁止变更

不使用试用键、虚构账号和模拟保存端，不接云写入、不猜测云环境、不改变 AppID。旧 `climbing_records` 等来源按原 ID 只读兼容，此单不导入或改写；清缓存不得清空全部微信存储或删除原图。

## 验收标准

- [ ] 首次无正式键时返回空档案，可用自己输入的岩馆建立场次；重载后原档案 ID、当前场次和线路一致。同日两场、同色同级两线各有独立 ID。读到损坏或不支持的已有数据须可见报错，保留原数据。
- [ ] 在正式 `climbingNote.training.v1.` 命名空间保存。测试逐项核对重开前后的结果、备注和本地日期。落盘失败不报已保存；重试同一操作只提交一次，新一次真实尝试有新 ID，两个页面的迟到操作和重复提交不覆盖新数据。
- [ ] 复用 v0.3 语义：抱石已确认完攀后只可显式更正指定原把；不增把数，保留 ID、原场次和备注。顶绳/先锋仍可继续记。失败后重试和再次完攀均有持久数据断言。
- [ ] 在没有 `wx.cloud` 或云初始化失败时，正式入口所需模块能加载，本机读写成功，旧云读请求有可判别的失败结果。普通清缓存前后对比训练键、照片索引和其他未授权键，断言其内容一致。
