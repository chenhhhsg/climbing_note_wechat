# T056 R1 保护逐把备注草稿

## 背景与问题

2026-11-20 复审在单线和原场逐把中复现。输入 A 把未提交的备注、切到 B，再回到 A，草稿被其原已保存备注替换。

## 开发范围（允许修改）

复用两页共用的编辑处理。草稿只存在所在页面实例中，按档案、场次、线路、原把 ID 隔离。切换或折叠后可回到原把继续编辑。明确取消才丢弃。保存读回确认成功后才释放，失败可重试。维持编辑代次和迟到输入、保存事件校验。

## 禁止变更

保留既有页面结构、记把按钮、撤销恢复、删除、视频和持久化格式。禁止访问实际用户档案或云环境。

## 验收标准

- [ ] 两页分别操作 A → B → A，A 的草稿仍在。保存 B 后 A 草稿及其已保存原值保持正确。
- [ ] 取消仅丢弃所选草稿。保存故障仍可继续输入和重试，实际读回后再释放。
- [ ] 跨档案、场次、线路和把次的旧代次或迟到事件不能读写别把。所有既有备注、撤销、删除回归通过。

## 建议验证命令

```powershell
node --test tests/training-record-note-withdraw.test.cjs
node --test tests/*.test.cjs
```

## 测试与人工验证边界

离线先复现旧行为，再在隔离档案验证两页真实处理器。原生验收两页按卡片实际展开、输入、保存和取消。手机数据不作为注入故障的测试资料。

## 回滚办法

撤销隔离分支的任务提交即可恢复原交互，既有本机备注仍按原保存规则读取。
