# T046 从原场小结先看本场逐把

[整项验收](../docs/product/界面改版-v1.1-整项验收.md)

## 背景与问题

小结点线路只传档案和线路 ID，直接打开跨场历史，无法先回看选定场次。

## 开发范围（允许修改）

保留「记录 → 原场小结」。小结点线带原档案、场次和线路 ID 进入现有「本场逐把」页，核对归属并标明原日期、岩馆与场次。该页主动点「线路历史」再去原线路跨场历史。返回文案与实际回到原场小结的落点对应，保留逐把的原备注、视频及既有显式操作。

## 禁止变更

浏览过程零写入，活动场与选中线路按原状态保留。缺参、失效与同名异线不以当前场顶替。保持历史数据、日期分组、旧云入口和照片视频索引。

## 验收标准

- [ ] 同一长期线路在两场各有把次，从第一场小结点该线只看到第一场原把次和正确场次身份。
- [ ] 主动进线路历史后看到原线路的两场记录和同一主照片、卡点。逐级返回原场逐把和原小结，回首页继续原活动场及线路，浏览前后档案一致。
- [ ] 同日多馆、同馆多场和跨午夜沿用原日期及 ID；零把与缺参仍有可理解状态，旧云汇总按原 ID 打开。

## 建议验证命令

~~~powershell
node --test tests/training-session-summary.test.cjs tests/session-route-flow.test.cjs tests/training-history.test.cjs tests/record-list.test.cjs tests/attempt-video.test.cjs
node --test tests/*.test.cjs
git diff --check
~~~

## 测试与人工验证边界

离线核对全链 URL、跨场及跨线夹具、档案字节与活动指针。原生和手机复查返回落点、主照片与原把视频。

## 回滚办法

回退原场逐把的导航与返回文案，验证原小结、旧记录和跨场线路历史持续可用。
