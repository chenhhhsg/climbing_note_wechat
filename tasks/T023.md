# T023 给已保存的一把关联相册视频

## 背景与问题

用户要从某一次实际尝试发起复盘。现有 media-check 是独立验证工程，正式场内页、历史页和本机把次还没有选片关联入口。 [批次验收](../docs/product/手机反馈与逐把视频-批次验收.md)

## 开发范围（允许修改）

在场内与历史把次行按稳定 ID 进入正式视频页；从相册选择一个视频，显示待确认状态，用户确认后持久保存本机档案、把次、片段及片源类型等关联元数据。临时文件不作永久有效承诺。复用原实验结论，兼容微信选项对象回调。仅在 G09、V05、PK03 的正式页面清单中加入本批视频页，保留原路由、tabBar、重复注册和缺文件检查。

## 禁止变更

不改原训练数据结构、用户照片和体能自测；旧汇总没有真实把次 ID 时保持只读。不上传或访问真实相册做自动化测试。

## 验收标准

- [ ] 同一条线已落盘 A/B 两把，只有 B 被选片并确认后出现关联；同色同级邻线、跨日原把 ID 和备注保持原值。从场内和历史打开 B，读到相同关联。待保存的把次不能挂片。
- [ ] 取消系统选择器或取消确认后可马上重选；迟到回调、切到另一把或快速双击确认不能串线或重复。写入前失败及落盘后丢应答后重试同一操作，最终只有一条关联。
- [ ] 首次启动或断网无云能力可记把，视频功能为可选；不在缺省路径复制相册原件。正式包注册新页，试用目录继续排除。

## 建议验证命令

node --test tests/attempt-video.test.cjs
node --test tests/*.test.cjs
git diff --check
~~~

## 测试与人工验证边界

使用内存存储、虚构相册响应复现回调与写入失败；独立 QA 实际点击两处入口，使用开发者工具真实选片器。真机权限列在负责人验收单。

## 回滚办法

在隔离候选中按依赖逆序撤回本单的实现，复跑前序用例。保留已存在的持久媒体、用户记录和索引，回退版本只读取其支持的格式。
