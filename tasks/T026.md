# T026 按次选择保留本机视频副本，支持离线重开与移除

## 背景与问题

临时相册路径可能失效。按改造计划第 5 节，长期回放副本由用户另行选择。本单让用户能在同一手机重开 B 后离线回看。 [批次验收](../docs/product/手机反馈与逐把视频-批次验收.md)

## 开发范围（允许修改）

在视频页提供明确的本机留存、移除副本与可用空间提示。只对选中片段写入本机档案专属持久目录；先核对可播放文件、再提交引用，替换成功后才释放无引用旧副本。用独立视频索引和目录接入已批准的清缓存保护范围，不修改普通清缓存的全局策略。

## 禁止变更

不默认复制，不清空微信存储，不删除无法证明归属的文件；不调用云存储，不改生产环境。

## 验收标准

- [ ] 缺省选片/播放/记把不会创建持久视频副本；明确选择留存后，临时文件失效、普通清缓存、退出再打开，B 的同一段视频和时间点仍可离线回看。
- [ ] 空间不足、文件复制失败、索引写失败或重复确认，能看到原因并可重试；无丢失旧可读副本、重复/串线引用，重启能处理本操作遗留的临时副本。
- [ ] 移除本机副本后，原把、备注、标记与系统相册原件仍在；缺原片时显示重选。其他把、其他档案、线路照片和自测不受影响。对已有无视频档案和只有临时关联的旧记录可直接读取。

## 建议验证命令

~~~powershell
node --test tests/attempt-video-files.test.cjs
node --test tests/*.test.cjs
git diff --check
~~~

## 测试与人工验证边界

离线模拟空间不足、各阶段写失败与缓存清理；QA 使用合成样片在隔离文件根核对持久文件内容。手机微信真实存储配额、权限及退后台重开列为现场验证。

## 回滚办法

在隔离候选中按依赖逆序撤回本单的实现，复跑前序用例。保留已存在的持久媒体、用户记录和索引，回退版本只读取其支持的格式。
