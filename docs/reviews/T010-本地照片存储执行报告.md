## 3. 数据契约摘要

专用位置：

```text
climbingNote.gymLogTrial.photos.v1        照片与归属索引（受保护，INDEX_VERSION=1）
climbingNote.gymLogTrial.photoThumbs.v1   缩略图元数据（可重建，THUMB_CACHE_VERSION=1）
<USER_DATA_PATH>/gym-log-trial-photos/v1/main/photo-<seq>.jpg
<USER_DATA_PATH>/gym-log-trial-photos/v1/thumb/photo-<seq>.jpg
```

索引关键结构：

```text
routes:     { ownerId, datasetId, routeId, photoId, rev, activeOpSeq }
photos:     { photoId, ownerId, datasetId, routeId,
              storage: { type: 'local', location },
              width, height, bytes: { main, thumb }, createdAt }
operations: { opId, seq, instanceId, ownerId, datasetId, routeId,
              kind: add|replace|remove,
              status: started|committed|failed|aborted,
              photoId, basePhotoId, baseRev, startedAt, finishedAt, error }
```

- 归属在操作启动时固定；`ownerId`/`datasetId` 由调用方显式注入，`routeId` 使用稳定线路 ID。
- `photoId` 不使用临时路径；`storage.type` 与 `storage.location` 分开。本轮只有 `local`。
- 新增/更换先写 `main`+`thumb` 文件，再单键写索引并提交 operation；成功只在两步都完成后返回。
- 移除先提交“不再引用”的索引，再删文件；删文件失败返回 `file-delete-failed` 与 `associationRemoved: true`。
- `recover()` 在服务实例初始化时调用：中止 `started` 操作、修剪缩略图缓存、只删除 `main/thumb` 中无索引引用且不属于进行中操作的 `photo-*.jpg`；索引损坏时拒绝重建和删除。
- 稳定错误码：`missing-owner`、`missing-dataset`、`missing-route`、`missing-source`、`index-broken`、`index-write-failed`、`compress-failed`、`file-write-failed`、`thumbnail-failed`、`already-has-photo`、`no-photo`、`operation-in-progress`、`stale-operation`、`missing-file`、`file-delete-failed` 等。

### 5.2 PS03 原子结果与恢复

| 注入点 | 结果 |
|---|---|
| 压缩失败 | `compress-failed`；无照片记录、无主图/缩略图、operation `failed` |
| 尺寸读取失败 | `source-unreadable`；同上 |
| 主图写入失败（留下部分文件） | `file-write-failed`；部分文件被清理，无假成功索引 |
| 缩略图写入失败 | `thumbnail-failed`；主图也被清理，因为未提交 |
| 启动时索引写入失败 | `index-write-failed`；没有调用压缩/写文件，缓存键不存在 |
| 提交时索引写入失败 | 返回失败；路由为 `none`，新主图被清理；同 opId 重试后成功且只留一个主图 |
| 更换失败 | 旧 photoId/位置/文件保持可读；新文件清理；同 opId 重试成功后旧文件删除、只留一个新主图 |
| 步骤间中断 + `recover()` | 未完成 operation 变 `aborted`；已引用主图/缩略图保留；迟到结果返回 `stale-operation` 并清理自己的文件；同 opId 可重试 |
| 孤立文件 | `main/photo-999`、`thumb/photo-999` 无索引引用，被 `cleanupOrphans()` 删除；引用中的 `photo-1` 保留 |
| 索引损坏 | `index-broken`；不自动重建、不删用户文件；读取抛错时 `index-read-failed` 同样不删 |

### 5.3 PS04 重复与乱序

- 同 opId 串行重复：第二次 `duplicate: true`、同一 photoId，`writeMain` 只调用 1 次。
- 同 opId 并发：第二次 `operation-in-progress`，不派发第二次写文件。
- 不同 opId 并发：较新操作先提交，较旧操作返回 `stale-operation`；索引只保留较新 photoId，旧文件清理。
- 旧更换回调 + 移除：旧更换在移除提交后完成，不恢复照片；最终路由 `none`、无照片记录、无文件。
- 实例重建后 `recover()` 不改变已提交 operation，读取仍指向原 photoId。
- 分别断言 `routes[].photoId`、`photos[]`、`operations[].status` 与实际文件，而不只看返回文案。

### 5.4 PS05 移除与缺失

- 移除 L1 成功：只删 L1 的主图/缩略图；L2、B、其他数据集的照片与文件保留。
- 移除索引写入失败：旧照片/缩略图/关联仍可读；同 opId 重试成功。
- 删除文件失败：返回 `ok:false, code:'file-delete-failed', associationRemoved:true`；路由已无照片，文件仍在；同 opId 重试清理成功并返回 `duplicate:true`，不虚报首次成功。
- 缺主图：`getRoutePhoto`/`getPhoto` 返回 `missing-file`、`status:'missing-file'`、`photo` 状态与同线路归属；不返回 L2 的照片；`rebuildThumbnail` 也返回 `missing-file`。
- 缩略图缺失：主图仍可读，`status:'ready-thumb-missing'`；`rebuildThumbnail` 从主图重建后恢复 `ready`。

   `http://tmp/...` 临时路径正常。首轮保存失败于“缩略图压缩”，因为当时缩略图从持久主图生成。
   已改为从“刚压缩好的临时主图”生成缩略图，保存流程随后通过。
   `rebuildThumbnail` 仍以持久主图为源；该入口在开发者工具受限，真机或 T012 的页面级临时源
   另验，不能把开发者工具结果当成真机通过。
