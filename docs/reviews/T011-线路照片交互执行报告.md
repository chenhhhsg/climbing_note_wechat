## 3. 实现要点

### 3.1 身份与数据集

- `utils/trial-profile.js` 集中定义：
  - `TRIAL_OWNER_ID = 'trial-user-local-a'`
  - `TRIAL_DATASET_ID = 'trial-dataset-local-1'`
- 两者只用于本机试用归属检查，不是微信账号；页面不读取昵称、头像或登录态。
- `store.js` 的客户端状态加入 `datasetId`；旧缓存没有该字段时按默认数据集读取，
  原场次、线路、尝试、备注不改写，下次写入才持久化。
- 安全重置时用 `nextTrialDatasetId()` 轮换数据集，避免重建的 `route-local-1`
  再次挂上旧数据集照片。

### 3.2 页面照片状态

| 状态 | 页面表现 |
|---|---|
| `none` | “添加线路照片（可选，可稍后添加）”，显示拍照/相册 |
| `preview` | 显示所选临时图，“确认保存/取消”；确认前不写文件或索引 |
| `saving` | “照片保存中…”；不显示成功，不锁住记尝试 |
| `saved` | 显示缩略图/主图，“照片保存在本机”，可查看大图、更换、移除 |
| `failed` | 失败原因 + “重试保存/重试移除/重试清理”；更换失败时旧图仍可预览 |
| `missing` | “本机照片不可用，可重新添加”；只影响该线路，可重新添加替换关联 |
| `error` | 索引/读取失败，提供“重试读取”，不自动重建或删除 |

### 3.3 四处入口

| 入口 | 读取/写入 |
|---|---|
| 新建线路 | 表单先预览，创建成功后保存；照片失败不回滚线路 |
| 今日当前线路 | 当前 `routeId` 的主照片卡片 |
| 历史/选线路 | 列表缩略图 + “加照片/换照片”按钮，先选中线路再选来源 |
| 线路详情 | 完整主图 + 原生 `wx.previewImage`（可双指缩放），可添加/更换/移除 |

### 3.4 重置试用数据

- 有照片时先弹窗：说明照片文件和关联索引属于用户资料；取消保留全部资料与账本；
  确认后清空场次、线路、尝试与模拟账本，并把客户端切到新数据集。
- 旧照片文件与索引不删除，保留在旧数据集；新数据集的同编号线路不会读取旧照片。
- 没有照片时直接重置，数据集保持不变。
- 普通清缓存、容量统计和旧数据集照片管理留给 T012。
