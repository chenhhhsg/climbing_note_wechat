### 1.3 验证页行为（第二轮）

- **选片**：`wx.chooseMedia({ count: 1, mediaType: ['video'], sourceType: ['album'] })`，限定相册、视频、单选。
- **唯一身份**：每次 `useVideo` 递增序号，生成新 `token`（`video-N`）和新原生节点 id（`media-check-video-N`）。WXML 用 `wx:for="{{videoInstances}}" wx:key="token"` 创建节点；key 变化时旧节点销毁、新节点创建。token 写在节点 `data-video-token` 上，事件身份随原生节点走，不靠修改页面状态反推。
- **旧事件隔离**：`onVideoLoadedMetadata` / `onVideoPlay` / `onVideoPause` / `onVideoTimeUpdate` / `onVideoError` 都先比较事件 `currentTarget.dataset.videoToken` 与 `activeToken`；不匹配直接返回。换片后 A 的迟到 metadata、timeupdate、error、play、pause 不会写入 B。
- **上下文跟随**：`getVideoContext` 以当前 `videoInstances[0].domId` 创建/缓存 `wx.createVideoContext`；换片时清空缓存，跳转只发给当前组件。离线测试断言新旧 context id 不同，旧 context 不再收到 `seek`。
- **换片重置**：`useVideo` 清空 `ready`、时长、宽高、播放状态、`currentTime`、跳转目标、短片原因和错误；B 的元数据到达前 `seekDisabled=true`。
- **就绪**：只有当前节点 `bindloadedmetadata` 回报有效时长后才 `ready=true`。元数据只代表时长/宽高，`currentTime` 保持 `null`、文案“尚未回报”，不假装已收到 0 秒位置。
- **跳转**：页面以 `TARGET_POSITION_MS = 5000` 接收报告时间点，仅在调用播放器边界除以 1000，发送 `seek(5)`。目标值（5000 毫秒 / 5 秒）与播放器 `timeupdate` 实际回报分开显示。
- **不足 5 秒**：元数据到达即设置 `seekDisabled=true` 并显示“视频时长不足 5 秒（x.xx 秒），无法跳转到第 5 秒”；按钮渲染为 disabled。方法内守卫再次检查时长，直接调用也不发送 `seek`。
- **取消/失败**：取消选片保留当前视频和节点身份；选择失败显示可重试错误；重新进入页面为新会话，不读缓存、不恢复临时路径。
- **会话隔离**：临时路径只保存在页面实例，不写缓存、不初始化云开发、不上传。
