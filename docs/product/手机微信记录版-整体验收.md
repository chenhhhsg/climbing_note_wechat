# 手机微信记录版 · 一次岩馆训练的交付与验收

负责人在 v0.3 收尾后确定首个交付目标，并确认「先存本机，优先交付手机试用」。本批从本地 `main` 的 `3d7bd85` 起步，复用已人工验收的 `f56e069` 行为。使用者从正式小程序首页进入，记录自己的岩馆、场次和线路。交付顺序为本记录版在手机微信实际试用 → M2 关联把次视频、选片播放、上传和按时间点回看 → M3 AI 分析。[路线图](../../ROADMAP.md) · [改造计划第 3、4 节](../攀笔微信小程序改造计划_v0.2.md)

## 数据存在哪里

| 对象 | 首版约定 | 退出后怎样找到 |
|---|---|---|
| 实际岩馆、场次、线路、场内线路关联、逐把结果及备注 | 使用正式小程序的微信本地持久存储，为本机档案生成并持久化稳定 ID。拟用独立键前缀 `climbingNote.training.v1.`，按本机档案归属组织。记录日期使用训练所在地的本地日期；线路和把次均有稳定 ID。 | 首页重读当前场次和线路。历史按长期线路 ID 查原把，再按原日期和场次分组。同日多场各自保留。保存成功以本地持久写入为准，失败可重试原操作。 |
| 线路主照片 | 每条线一张可选。压缩后的原文件持久保存在 `wx.env.USER_DATA_PATH/training-photos/v1/<archiveId>/` 下；照片索引位于上述正式本机命名空间。索引分别保留照片 ID、本机存储类型、文件位置、所属档案及线路 ID。 | 路线重开时从索引解析本机文件。更换成功后再释放旧文件，普通清缓存只清可重建项。 |
| 既有云端历史 | 保留原 `climbing_records`，经现有本人有权限的列表/详情接口按原 `_id` 读取日期、地点、等级、状态、`attempts`、备注和图片引用。若已有经核实的 `climbing_sessions.routes[]` 来源，保留原归属和原结构，只读兼容。 | 从「旧记录」进入原详情。「尝试 5 次、完成」显示为一条历史汇总；浏览不拆出五把，不按同色同级猜线路，不向旧库写回。不具备云环境或权限时明确提示旧记录暂不可读，保留本机记录入口。 |
| 独立工程的既有试用记录 | 原导入目录、`climbingNote.gymLogTrial.*` 键和试用照片目录继续由原试用工程使用。正式版新档案首次启动为空，无预置岩馆、线路或模拟账本。 | 原记录继续从原试用工程回看。此批没有数据导入、迁移、跨设备同步或备份功能。 |

此处的档案 ID 用于本机归属，不承担云端登录认证。按同一手机、同一微信使用环境、同一小程序重开验收；微信移除小程序数据或更换设备超出本地保存能力。T004 继续跟踪真实云权限和 A/B 测试身份，缺少该环境只影响真实旧云记录的核验。新入口必须能在断网和云能力不可用时冷启动、建场、记把和回看。

## 开发顺序

| 顺序 | 交付给下一项的能力 |
|---|---|
| [T016 正式本机档案](../../tasks/T016.md) | 空档案、稳定 ID、持久读写、失败恢复、普通清缓存保护，正式页面可在云不可用时加载。 |
| [T017 首页与场内记把](../../tasks/T017.md) | 从首页开始或继续真实场次，创建/选择三类线路，逐把保存结果、备注及抱石误点更正。 |
| [T018 历史、详情与旧记录](../../tasks/T018.md) | 同一条线路跨日回看和接续；本机逐把与旧云汇总采用明确入口、各自保留来源。 |
| [T019 本机线路主照片](../../tasks/T019.md) | 拍照或选片、预览确认、持久保存、更换与移除；在完整正式工程走通下列训练场景。 |

负责人已批准 T016–T019，并将 [T020 体能自测](../../tasks/T020.md) 加入本批。五单由 ZCode 按顺序执行 `run-approved-task.ps1 -DevOnly`，后一单从前一单实际自测通过的提交起步。PM 记录各提交和退出码。整合后固定一个候选 SHA，由独立 QA 出一份需求级报告。返工后在新提交复验受影响项与核心训练流程。

## 一次训练的验收脚本

| 编号 | 现场操作 | 对照和预期 |
|---|---|---|
| R1 到馆与恢复 | 在手机微信打开候选正式首页，输入自己当天训练的岩馆，开始一场。返回首页、退出小程序并重开，点「继续本场」。 | 恢复同一场次和路线选择，不多建一场。可在同日主动另开一场，两场能分别查看。首屏无演示记录，旧云读取失败时也能完成这些操作。 |
| R2 两把与备注 | 在第一场新建蓝色抱石 V3，从相册选一张线路主照片并确认，连续记录两把未完成，给第二把写「抓到后向右摆」。另建一条同色同级不同线路。 | 第一条线恰好两把，第二把有备注；第二条线有不同 ID，不带前一条的把次或照片。试拍或选片后取消可立即重选，取消更换保留原照片。 |
| R3 跨日完攀与纠错 | 下个训练日从正式历史打开原线，在当日场次再记一次完攀。退出重开后，任选今日页或历史详情将那一把改为未完成，再正常记一次完攀。 | 更正前为两天、三把、一把完攀；更正后仍三把、零完攀；再记录后四把、一把完攀。原把 ID、日期、场次、第二把备注和照片保持。同一位置连续点更正只影响指定把。 |
| R4 绳攀与分级 | 新建时依次切换「抱石 V3 → 顶绳 → 选 5.10a → 先锋 → 抱石」。分别在顶绳、先锋线上记一把完攀，再记下一把。 | 不适用的等级清空并需重选；顶绳换先锋保留 5.10a。两条绳线可以继续记，类型、等级在重开后保持。 |
| R5 保存边界 | 断网记录并重开；另在同一候选的隔离夹具中模拟本机写满、写入前失败、落盘后界面未获确认，随后重试。对照片分别验证空间不足、确认更换、移除和普通清缓存。 | 断网可实际保存。持久写入失败有可见提示；重试原操作后只有一把，迟到回调不覆盖新结果。照片失败保留旧图，普通清缓存后场次、备注、索引和仍被引用的原图都在。 |
| R6 新旧回看 | 从「旧记录」打开有权限的一条旧汇总；用隔离夹具覆盖旧 ID 恰与本机线路 ID 同字、空库和读取失败。 | 原备注、汇总次数和图片引用可核对，旧汇总不计入本机逐把数。失败与空库状态可以区分，本机历史照常工作。无已核实云环境时登记「真实旧云记录待核验」，标明 T004 的前提。 |
| R7 自测与复测 | 从「我的」输入 9c 原方案的示例，核对全部评分边界，保存、重开、更正并另存复测。 | 19/20 分为 7c+、5.13a、约 V7，40 分的 V 级显示「暂无对应档」。核对分项、两个版本号及复测原始数据，实际场次、完攀和照片保持原值。 [完整评分与样例](9c攀岩体能自测-v0.1.md) |

**交付证据。** T016–T020 的开发自测基线命令为 `node --test tests/*.test.cjs`，本批规划时在 `3d7bd85` 运行 227/227，退出 0。QA 在固定候选复跑全套，记录正式根工程路径、候选 SHA、预览版本、机型、微信/基础库版本、本地日期、关键计数及脱敏截图。用已有 `scripts/check-package.cjs` 检查同一候选的正式包，确认包含新页面和运行依赖，排除 `devtools/` 及内部资料。所有测试照片和故障数据使用独立样例。

**现场通过条件。** 负责人手机微信从正式首页实际完成一场训练，退出并重新打开同一版本，核对记录、照片和备注；下个训练日回原线验证 R3。离线可用注入日期覆盖跨日，QA 报告须分别写明模拟日期和手机实测日期。真机、实际跨日或岩馆试用尚未完成时列为待验，保持负责人验收开放。记录版交付试用后，再安排视频。
