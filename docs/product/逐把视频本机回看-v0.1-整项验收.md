## 文件与数据

- 待确认片源只存在于当前预览。确认保存后把文件写入小程序用户目录中的档案专属视频目录。独立索引保存档案、原场次、线路、原把次、片段标识/版本、文件标识和实际字节。旧 v1 训练档案按原方式读取，缺原把次 ID 的历史汇总保持原样。[微信小程序文件系统](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/file-system.html) · [相册选择](https://developers.weixin.qq.com/miniprogram/dev/api/media/video/wx.chooseMedia.html) · [原生视频组件](https://developers.weixin.qq.com/miniprogram/dev/component/video.html)
- 替换依次验证新副本、提交新引用、清理无引用的旧文件。失败或提交结果不明时保留仍可能在用的文件，并按实际索引读回复原。移除回收小程序内副本，撤回把次仍保留原关联以供恢复。
- 视频占用显示按实际文件字节，空间判断考虑单片、总占用、替换峰值及照片余量。开发自测可注入低限额。最终产品阈值用手机样片定，以可核对的大小、清晰度和耗时为依据。遇到真实配额失败以系统结果给出提示，保留已保存内容。

## 同一候选的验收

| 场景 | 离线与开发者工具证据 | 负责人手机证据 |
|---|---|---|
| V1 · 同线两把 | A、B 均已保存，仅给 B 选片并确认。对比原档案、场次、线路和把次 ID，A 及同名异线均无关联。缺参、错档、旧汇总、待保存与撤回记录不提供写入。 | 原手机从相册选一段，预览后保存。返回明细时只有 B 显示「看视频」。 |
| V2 · 断网跨日回看 | 移除临时路径并重建存储适配器和页面。明细和原场次历史都定位到同一持久文件，字节对得上。原生工具用合成片记录实际播放与暂停，并记录缺文件、损坏、旧播放器事件的处理。 | 保存后结束小程序进程，在断网下重开已加载过的预览版，从原场次和跨日历史回看 B。记录微信版本、设备系统、播放画面和格式。按可用设备分别记录 iOS、Android，缺设备的系统标待验。 |
| V3 · 更换及移除 | 取消预览不创建副本，旧片版本与字节不变。确认更换后新片可播，旧副本只在提交完成且无引用时清理。移除重复点也只作用于当前小程序副本。 | 取消一次更换，旧片仍能播。确认替换后能播新片。移除后 B 及备注在，系统相册仍可找到原片。 |
| V4 · 撤回恢复与重试 | B 撤回、跨页、恢复后用同一 ID 回到原视频。核对迟到回调、双击、写入前失败、索引写失败、提交后回执丢失及清理失败。记录文件、索引和有效把数对照。 | 放回测试视频后撤回并恢复 B，恢复后能播原片，训练计数随原把次状态变化。 |
| V5 · 空间与清缓存 | 用受控预算或文件系统错误复现空间不足，旧片和其他数据仍可读，训练仍可记。普通清缓存前后比较视频、主图、卡点、训练、自测与未知文件。 | 用测试样片观察占用和真实失败提示，确认旧视频和照片可回看。应用内普通清缓存后，已保存视频和照片仍可播看。 |
| V6 · 本机与正式包 | 检查实际运行路径和网络记录，添加、播放、更换和移除均无视频上传。原生构建包含正式视频页，合成片、验证工程与内部资料留在包外。 | 只使用有权测试的本机样片，记录实际相册授权和格式结果。 |

按任务确认后的顺序，在独立协调工作区用 `run-approved-task.ps1 -DevOnly` 逐项给 ZCode。每项核对代理退出码、测试退出码和完整改动范围，并在其通过的提交上开始下一项。全部集成后，未参与开发的 QA 在同一冻结提交运行 `node --test tests/*.test.cjs`，完成 V1–V6 的对应检查，输出一份整项报告和裁决。手机验收使用同一提交的预览和步骤，记录真实选片、解码、配额和重开证据。现有试用档案与工程保留原状，自动化使用隔离的合成记录与文件。
