## 原生数据与操作约定

- 用本机训练档案 `climbingNote.training.v1.archive`，沿用 archiveId、sessionId、routeId 和原把次 ID。现有 `saveAttempt` 用 opId 识别已保存或待保存的同一把。撤回后仍须认得这个 ID；撤回、恢复应是带原目标及预期状态的明确动作。重复或过期请求在重开后同样不能把状态翻回去。
- 同一操作区保留线路名、原序号和结果。撤回后不能把刚点击的位置交给另一把或相反动作；恢复入口仍在该处附近且须有意点击。照片按线路关联，备注按原把关联。跨天已有的历史、归档清单和本地图片继续按原 ID 读取。
- 首页、场内、详情历史、有效完攀与待确认判定、统计、场次小结和想爬清单要使用一致的有效把次。旧档没有撤回状态时已提交把次全部有效。已有「改为未完成」保留该把，撤回减少一把，分别取证。旧云汇总继续只读。

## 一次完整训练的证据

| 场景 | 验证动作与预期 |
|---|---|
| 加线 | 从空场开始，首屏直接点「添加第一条线路」。分别取消新建、选本馆已有线、创建另一条线；核对 ID、关联数与当前选择，成功后可直接记结果，原线历史可读。另经底部「记录」进入「补录旧记录」。 |
| 换线 | 先用同色同级 A、B，再加入另外两条。首屏从线路名与「全部 4 条」换线；切到 B 再记一把，A 的结果、备注、照片不变；带长名称和已有照片、历史的场次再走一次。 |
| 同一把往返 | A 的第 3 把附备注，记录原 ID。撤回后 3→2，切到 B、回 A、退出重开仍为 2；恢复后 2→3，ID、备注、原序号保持。检查已撤回时的迟到保存和已恢复时的迟到撤回。 |
| 按钮位置与失败 | 在 320×568、390×844 对照样稿，并记录微信模拟器的实际可用视口。分别在同一屏幕坐标连续点击撤回两次和恢复两次，核对按钮矩形、实际命中目标、落盘前后计数。注入写前失败和写成后回执丢失，重试同一意图，无额外把次、无串线。 |
| 完攀与全档对账 | 抱石唯一完攀撤回可再记，恢复后锁定。覆盖其他有效或待确认的抱石完攀、绳线重复完攀、已撤回后再产生新把、同日两场及跨天回看。逐项核对历史、统计、小结、清单与照片；原「改为未完成」保持总把数。 |
| 负责人手机与首次使用 | 负责人在同一候选的手机预览中完成一次训练并重开，核对触控与数据。请一位未看过教程的试用者独立完成加线、换线、误记撤回；记录首次点到的入口、停顿及求助位置。保留设备、视口及实际操作结果，未执行项标待验。 |
