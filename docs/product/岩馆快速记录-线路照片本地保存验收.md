## 用户结果与首版范围

用户用一张照片记住长期线路；在同一手机上跨场次、跨天找回同一线路时能看到它。每条线路有零张或一张主照片，照片不是场次或单次尝试的附件。用户可以先保存线路和记尝试，之后再补照片。

入口覆盖新建线路、今日攀爬、线路详情和历史选线。拍照或相册选取后先预览、再确认；列表用缩略图，详情可打开完整主照片并缩放。沿用粉笔白、炭黑的既有设计。使用“添加线路照片”“照片保存在本机”“已保存到本机”等明确文字。

确认保存后，压缩主照片必须成为可重启读取的持久文件，并保存用户、长期线路、照片之间的关联。主照片和关联索引作为用户资料保护；缩略图等可重建内容才可作为普通缓存清理。文件写入和关联保存都成功后，才显示“已保存到本机”。

首版不增加多图相册、自动云上传、跨手机同步、真实旧数据迁移、照片 AI 分析或完整离线记录能力。线路照片本地保存不依赖新增云照片存储；稳定身份和正式线路接入的现有缺口仍须在开发任务中处理或明确列为未验。

## 验收准备

准备两条颜色、难度相同但稳定 ID 不同的线路 L1、L2；准备两个独立测试用户 A、B，以及可区分的样例照片 P1、P2、P3。用同一手机、不同日期的场次验证复用。所有样例须经授权，不把真实个人照片或身份字段提交仓库。

离线逻辑测试可使用可控的身份、文件系统和存储替身，分别注入压缩失败、文件写入失败、关联保存失败、文件缺失、空间不足与异步回调乱序。真机验收另用微信实际拍照、相册、文件读写与重启流程取证。替身通过不能代替真机身份隔离或持久化证据。

## 首版产品验收要求

下表为待实施的验收标准，当前不表示功能已通过。每个编号在后续开发任务与 QA 报告中保留，以便追踪证据。

| 编号 | 操作与故障条件 | 可观察的通过条件 | 必需证据 |
|---|---|---|---|
| LP01 可选与单图 | 新建 L1 时跳过照片，记两次尝试，再从相册添加 P1；已有照片时再次添加 | 无图也可创建线路、记尝试；每条线路最多一个当前主照片引用，再添加走更换流程；两次尝试的 ID、归属与备注不变 | 页面逻辑测试及入口走查 |
| LP02 选片与权限 | 分别从拍照和相册选取；预览后取消或确认；拒绝拍照权限 | 确认前不替换已有照片；取消后原关联不变；拒绝权限时可改用相册或稍后添加；照片失败不阻止记录尝试 | 真机选片、取消与拒绝权限记录 |
| LP03 持久保存 | 确认 P1，完成保存后退出微信再重开；逻辑测试让选择器的临时文件失效 | 文件和关联均完成后才提示成功；重开后仍能加载缩略图与主照片；读取不依赖选择器临时路径 | 独立断言文件存在与索引引用，另附真机重开证据 |
| LP04 跨天复用 | 周四在 L1 记两把，周日从历史回到 L1 再记一把 | 历史选线、今日页和详情显示同一照片；照片不因新场次重复保存；仍为两天三把，原备注保留 | 页面操作、尝试统计与持久文件数量对照 |
| LP05 线路区分 | 同一用户给 L1、L2 分别保存 P1、P2 | 两条同色同级线路的各入口各显自己的照片；修改 L1 不改变 L2 的照片或尝试 | 线路 ID、照片关联与页面显示断言 |
| LP06 迟到回调 | 给 L1 保存照片时切到 L2；另测离开页面、重进及同线再次更换或移除 | 原操作只作用于发起时的用户和 L1，不写入 L2、不覆盖当前页面的其他线路；较早回调不覆盖后来成功的更换或恢复已移除照片 | 可复现的乱序测试，分别核对文件、索引和当前页面 |
| LP07 保存失败与恢复 | 分别注入压缩、文件写入、关联提交失败；重开后重试；重复点击保存 | 原处显示失败与重试入口；未完整落盘不报成功；旧照片和尝试保持可用；恢复后只有一份有效主照片关联；中途产生的孤立文件可被识别并安全清理 | 各失败点前后文件和索引快照、重试结果 |
| LP08 更换 | P1 已保存，选择 P2；先模拟失败，再成功更换 | 失败时 P1 可继续查看；P2 持久文件和关联都成功后，各入口切换为 P2；清理不再被引用的 P1 文件，不能删除仍有有效引用的文件 | 失败保旧、成功切换及引用检查测试 |
| LP09 移除 | 对本机唯一副本执行移除，分别取消、确认及模拟移除失败 | 确认前说明移除后需重新添加；取消保持原状；成功后各入口无照片且可重新添加，照片占用相应减少；失败不虚报已删除，留有可恢复状态；尝试记录不变 | 交互与失败注入、索引和文件占用对照 |
| LP10 压缩与预览 | 用实际岩馆样例保存并放大；事先标记起点、终点及至少三处岩点 | 完整预览保留线路范围，标记位置可逐项辨认；记录压缩前后尺寸及实际字节数；列表使用缩略图；跨天查看不新增主照片副本 | 真机原图与保存图对照、样例检查表、字节统计 |
| LP11 空间提醒 | 模拟达到提醒线、超过可保存预算及实际写入报空间不足 | 展示照片已用空间；达到提醒线有管理入口；不足时说明原因并可重试或取消，已有照片与尝试不丢失；更换需计入新旧文件共存余量；不自动淘汰唯一主照片 | 总工确定的预算与阈值、边界测试、真机错误提示 |
| LP12 普通清缓存 | 有主照片、关联索引和可重建缓存时，从应用实际“清除缓存”入口操作，再重开 | 主照片及索引保留，L1、L2 仍能加载与预览；可重建缓存可清除或重建；不得把照片或索引列为无提示清理对象 | 实际入口走查，清理前后文件与关联比较及真机重开 |
| LP13 用户隔离 | A 保存 P1，切到 B，再切回 A；另测 A 保存途中切到 B | B 不展示、预览、更改或移除 A 的照片；同名、同线路编号不能混用关联；A 回来仍读到自己的照片；迟到操作不写入 B 的索引或界面 | A/B 替身隔离测试及真实微信身份切换证据，分别记录 |
| LP14 离线与文件缺失 | 已保存照片且本地索引可用时断网预览；再模拟文件丢失或另一设备无文件 | 断网仍可查看并缩放本机照片；无文件时显示“本机照片不可用，可重新添加”，不显示其他线路照片，不虚报云同步或永久丢失的文件已恢复 | 逻辑缺失文件测试、真机断网预览证据 |
| LP15 回归边界 | 完成添加、更换、移除、清缓存后，重放既有跨天三把、同日多场、旧汇总、丢回执重试 | 原任务的归属、备注、三把统计、旧汇总只读及原操作重试规则继续通过；既有无照片数据可正常读取 | 实际候选上的既有回归与新增照片用例 |

LP10 的 300–800 KB/张来自 v0.2，是压缩试验目标，不是已经定下的硬上限。以样例可辨认结果和占用记录确定最终参数；不以一句“照片清晰”替代证据。LP11 的预算、提醒线和更换预留量由总工在任务中具体化，并在实施时复核平台文件配额与可用的计量方式；不按理想单图大小承诺可保存张数。

“普通清缓存”指应用提供的缓存清理入口。微信或系统移除小程序本地数据、卸载、换机后的文件丢失，按 LP14 提示重新添加；首版不承诺本机副本在这些情况下仍存在。

## 后续云迁移的保留条件

当前只要求本地设计保留迁移能力，实际上传与云引用切换须由用户以后确认，并另立开发任务。

- 照片的逻辑标识与存储类型、保存位置分别表达；用户与长期线路的关联不能只靠临时路径或当前页面状态。通过统一保存、读取和移除入口使用照片，具体字段名由总工确定。
- 同一照片从本机迁往云端时保留照片标识；本机路径和云端文件位置可分别记录，不能把旧本机路径当成跨手机可访问地址。
- 未来迁移必须由仍持有该文件的手机执行。上传成功且确认云文件可用之后，才切换线路引用；上传失败或切换失败可重试，并保留原本机可用状态。
- 文件已丢失、仅剩索引时，要求重新添加；不能把其他手机的路径作为待上传文件。迁移是否删除本机副本届时另定，本次不实施。

这些条件在本地阶段通过数据契约和接口审查验证可演进性；云端上传、跨设备读取和真实迁移不能在本轮标记为已验证。
